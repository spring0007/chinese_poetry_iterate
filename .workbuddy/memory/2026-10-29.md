## 修复构建中断：全唐诗分片 JSON 逗号错误 + 孤儿标点段清理 + uid 重映射

### 现象
`python poetry-pipeline/build.py` 在 `sources.load_json` 抛
`JSONDecodeError: Illegal trailing comma before end of array: line 1528`。

### 根因
当天 20:06 的提交 `c4b8910`（「更新数据」，81 个全唐诗文件 +125,532/−80,044 行）
在做数据清理：删 `paragraphs: ["。"]` 的空记录、删正文里的校注与来源引用
（如「杨文生编著.王维诗集笺注第2版[M].成都：四川人民出版社,2018」、
「（见光绪二年刊《灵宝县志》卷八《艺文》下。」）。**删元素时没同步修正分隔逗号**，
产生三类语法错误：

| 形态 | 例子 | 修法 |
|---|---|---|
| 数组末项尾逗号 | `"识尽无生理，乃觉出凡笼。",` + `],` | 删逗号 |
| 相邻字符串缺逗号 | `"…终始。"` + `"）。"` | 补逗号 |
| 元素与 `]` 同行 | `"…不朽。"],` | 按前两类处理 |

`git show 7629dad:文件` 可解析（1000 条），`c4b8910` 版坏 → 坏数据随该提交入库。
共 **3 处**：`poet.tang.53000.json` 行 1528/6603、`poet.tang.56000.json` 行 4773。

### 修复内容
1. **JSON 语法 3 处**（就地修，不回滚——回滚会丢掉清理成果）。记录数 1000→968 / 1000→989。
2. **清理 2,000 段孤儿标点**：全库 1,999 条记录的 `paragraphs` 里混有 `）。`(1,701)、`。`(296)、
   `）`(1)、空串(2)。涉及 13 个文件（全唐诗 8 个分片为主，魏晋 6、御定 2、宋诗 2、近现代 1）。

### 踩坑记录
- **`heat-scores.json` 的格式是「CRLF + indent=0 + 严格字典序 + 末尾 CRLF」**。
  用 `json.dump(indent=2)` 重写会让 329,202 行全部重排（diff 爆炸）。
  正确复现方式：`json.dumps(dict(sorted(d.items())), ensure_ascii=False, indent=0).replace("\n","\r\n") + "\r\n"`。
- **`extras/*.jsonl` 是 CRLF 单行紧凑 JSON**，必须 `newline=""` 读写，替换 `'"i":"<uid>"'` 片段而非重新序列化。
- **热度挂接用「重算的 make_uid」而不是 `p.uid` 字段**（`build.py:_attach_heat_json`）。
  实测 **4,157 首（1.19%）「库 uid ≠ 重算 uid」，全部是 `author_uid=''` 的佚名诗**——
  这些诗的 uid 生成时 author 是「佚名」、挂接时被置空，两端算不出同一个 uuid5。
  **后果：佚名诗的热度分从来没挂上过**（heat 键按库 uid 写，挂接按空作者重算查）。
  这是 3.x 就存在的既有 bug，本次未修（改 make_uid 语义风险大，且佚名唐诗约 1,835 首，影响 0.5%）。
- 源数据分片有三种 `paragraphs` 形态，清洗脚本必须同时支持：多行块、单行块
  （`"paragraphs": ["很长一句"],`）、元素与 `]` 同行（`"…"],`）。
- 清点发现 51000 那个分片块内**有空行**，重写时必须原位置保留，否则格式变化。
